# Repository Cleanup - 2025-01-05

## Summary

Cleaned up redundant bootstrap scripts and refactored Terraform to embrace full GitOps approach where ArgoCD manages all Crossplane providers from `infra-definitions/`.

## Changes Made

### 1. Deleted Unused Bootstrap Scripts

**Removed files:**
- `bootstrap/crossplane/crossplane.sh` - Manual Crossplane installation script (replaced by Terraform)
- `bootstrap/crossplane/argocd.sh` - Manual ArgoCD setup script (replaced by Terraform)

**Reason**: These scripts were never executed. Terraform in `bootstrap/terraform/eks-bootstrap/main.tf` handles all installation via Helm.

### 2. Deleted Redundant Terraform Provider Templates

**Removed directory:**
- `bootstrap/terraform/eks-bootstrap/providers/` (entire directory with all subdirectories)

**Removed files:**
- `providers/upjet-aws/provider.yaml` (template)
- `providers/upjet-aws/runtime-config.yaml` (template)
- `providers/upjet-aws/provider-config.yaml` (template)
- `providers/aws/*` (entire directory - never used, enable_aws_provider=false)
- `providers/kubernetes/*` (entire directory - deployed at bootstrap, not needed in Git)
- `providers/helm/*` (entire directory - deployed at bootstrap, not needed in Git)

**Reason**:
- Duplicated what's in `infra-definitions/providers/`
- Version mismatch: Terraform used v1.6.0, infra-definitions uses v2.1.1
- ArgoCD now manages providers from `infra-definitions/` as the single source of truth

### 3. Refactored Terraform (GitOps Approach)

**File: `bootstrap/terraform/eks-bootstrap/main.tf`**

**Removed** (lines 393-710):
- All provider deployment logic (upjet-aws, aws, kubernetes, helm)
- kubectl_manifest resources for providers, runtime configs, and provider configs
- Complex provider configuration locals

**Added** (simplified to ~30 lines):
- Single IRSA role module (`module.crossplane_irsa`) for AWS authentication
- Supports both provider-aws-* and provider-upjet-aws-* service accounts
- Added output: `crossplane_irsa_role_arn`

**Before**: Terraform deployed providers → ArgoCD managed updates (conflict risk)
**After**: Terraform creates IRSA role → ArgoCD deploys everything from Git

## Architecture After Cleanup

### Bootstrap Flow (One-Time)

```
Terraform Apply
  ├─ Creates EKS cluster
  ├─ Installs Crossplane (Helm)
  ├─ Installs ArgoCD (Helm)
  ├─ Creates Crossplane IRSA role
  └─ Outputs: crossplane_irsa_role_arn
```

### GitOps Flow (Continuous)

```
Git Commit → ArgoCD Sync → Crossplane Providers → AWS Resources
```

**ArgoCD deploys from Git:**
- `infra-definitions/providers/` → Provider packages (v2.1.1)
- `infra-definitions/shared/configs/provider-configs/` → Runtime configs and ProviderConfigs
- `infra-definitions/xrds/` → Custom resource definitions
- `infra-definitions/compositions/` → Infrastructure templates
- `environments/{env}/infrastructure/` → Resource claims

### Separation of Concerns

**Terraform Responsibilities** (bootstrap only):
- EKS cluster creation
- Core component installation (Crossplane, ArgoCD, cluster-autoscaler)
- IRSA role creation for AWS authentication
- Network infrastructure (VPC, subnets, NAT gateway)

**ArgoCD Responsibilities** (continuous GitOps):
- Crossplane provider deployment and updates
- XRDs and Compositions deployment
- Infrastructure resource claims
- Application workloads
- Cluster add-ons (cert-manager, external-dns, nginx-ingress)

## Benefits

1. **Single Source of Truth**: All Crossplane configuration in Git via `infra-definitions/`
2. **Version Consistency**: No more v1.6.0 vs v2.1.1 conflicts
3. **Simplified Terraform**: 320 lines removed, clearer responsibilities
4. **GitOps Purity**: All infrastructure changes via Git commits
5. **Easier Updates**: Change provider versions in `infra-definitions/` and push
6. **No Duplication**: Removed redundant provider configurations

## Migration Notes

### For Existing Clusters

If you have an existing cluster deployed with the old Terraform:

1. **IRSA Role Already Exists**: The old Terraform created the IRSA role
2. **Providers Already Deployed**: Existing providers will continue working
3. **Update Path**:
   ```bash
   # Get current IRSA role ARN
   terraform output crossplane_irsa_role_arn

   # Update infra-definitions/shared/configs/provider-configs/aws-upbound-runtime-config.yaml
   # with the correct ARN

   # ArgoCD will take over management on next sync
   kubectl apply -f environments/dev/argocd/root-apps.yaml
   ```

### For New Clusters

1. **Run Terraform bootstrap**:
   ```bash
   cd bootstrap/terraform/eks-bootstrap
   terraform init
   terraform apply -var-file=raiden.tfvars
   ```

2. **Get IRSA role ARN**:
   ```bash
   terraform output crossplane_irsa_role_arn
   ```

3. **Update runtime config**:
   Edit `infra-definitions/shared/configs/provider-configs/aws-upbound-runtime-config.yaml`
   with the IRSA role ARN from step 2

4. **Deploy ArgoCD root app**:
   ```bash
   kubectl apply -f environments/dev/argocd/root-apps.yaml
   ```

5. **Watch ArgoCD deploy everything**:
   ```bash
   kubectl get applications -n argocd -w
   ```

## Verification Steps

After applying these changes:

1. **Verify IRSA role exists**:
   ```bash
   terraform output crossplane_irsa_role_arn
   ```

2. **Verify ArgoCD applications deploy**:
   ```bash
   kubectl get applications -n argocd
   # Should show: dev-crossplane-providers and dev-crossplane-platform as Synced/Healthy
   ```

3. **Verify providers are installed**:
   ```bash
   kubectl get providers
   # Should show: provider-upjet-aws-s3, provider-upjet-aws-ec2, etc. as HEALTHY
   ```

4. **Verify provider configs work**:
   ```bash
   kubectl get providerconfigs
   # Should show: default ProviderConfig
   ```

5. **Test infrastructure provisioning**:
   ```bash
   kubectl apply -f environments/dev/infrastructure/storage/test-bucket.yaml
   kubectl get bucket
   # Should provision S3 bucket successfully
   ```

## Rollback Plan

If issues occur, rollback is straightforward:

1. **Revert Git changes**:
   ```bash
   git revert <commit-hash>
   ```

2. **Re-apply old Terraform** (if needed):
   ```bash
   git checkout <old-commit>
   cd bootstrap/terraform/eks-bootstrap
   terraform apply -var-file=raiden.tfvars
   ```

3. **Providers will reconcile**: Crossplane will detect and fix any drift
